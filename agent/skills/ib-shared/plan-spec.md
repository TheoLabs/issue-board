# 기획서 작성 스펙 (단일 원본)

한국어 마크다운 기획서의 정규 템플릿. 대시보드가 **표는 표로, 블록쿼트는 콜아웃 박스로**
렌더하므로 아래 표현 규칙을 지킨다 — 반복 속성은 표, 판단 · 경계 · 핵심은 콜아웃.

**섹션은 반드시 `## N. 제목` 형태로 번호를 매긴다** (아래 순서 · 번호 고정):

```
# <프로젝트명>

## 1. 개요 / 목적
> 🎯 **목적** — 한 줄 핵심(엘리베이터 피치)을 블록쿼트 콜아웃으로.
(이어서 배경 1~2문단)

## 2. 타깃 사용자 & 유스케이스
| 페르소나 | 니즈 | 핵심 유스케이스 |
| --- | --- | --- |

## 3. 핵심 기능 (MVP)
| 우선순위 | 기능 | 설명 |
| --- | --- | --- |
(우선순위는 **`높음` / `보통` / `낮음`** 중 하나로만 — 대시보드가 색 chip으로 렌더.
**각 행이 이후 이슈 분리의 단위**가 된다.)

## 4. 범위 밖 (Out of Scope)
> ⚠️ **범위 밖** — 이번 버전에서 하지 않을 것들. 목록으로.

## 5. 비기능 요구사항
| 항목 | 요구사항/기준 |
| --- | --- |
(성능 · 보안 · 확장성 · 접근성 등)

## 6. 성공 지표
| 지표 | 목표값 | 측정 방법 |
| --- | --- | --- |

## 7. 테스트 시나리오
| # | 시나리오 | 절차 (핵심 흐름) | 기대 결과 |
| --- | --- | --- | --- |
(핵심 유스케이스를 커버하는 E2E 인수 시나리오. 절차는 `A → B → C` 흐름으로 간결히.
세부 테스트 케이스는 각 이슈의 "완료 조건"에 둔다.)

## 8. 핵심 가정 / 미결 질문
> 📝 **가정/미결** — 확정 안 된 가정과 열린 질문을 콜아웃으로. (리스크라 눈에 띄게)
```

## 규칙

- 섹션 제목은 `## 1.`, `## 2.` … 로 **번호를 유지**한다.
- 콜아웃은 반드시 블록쿼트(`>`)로, 이모지 + 굵은 라벨로 시작 (대시보드가 톤을 구분).
- 추측으로 지어내지 말고, 확정된 것과 가정을 구분해 "핵심 가정 / 미결"에 적어라.
- 핵심 기능 표의 **각 행**(우선순위 | 기능 | 설명)이 이후 이슈 분리(에픽)의 단위가 된다.

## 언어 규칙 (유비쿼터스 언어)

기획서는 **기획자 · 개발자 · 보고를 받는 사람이 모두 같은 뜻으로 읽어야 하는 문서**다.
개발자만 아는 어휘로 쓰면 나머지 둘이 읽어낼 수 없고, 같은 대상을 부서마다 다른 이름으로
부르면서 의미가 갈라진다. 도메인 용어로 쓰고, 구현 어휘는 빼라.

- **"누가 무엇을 할 수 있다"로 쓴다.** "무엇을 어떻게 구현한다"가 아니다.
- **구현 세부는 기획서에 넣지 않는다** — 테이블 · 컬럼 · API/엔드포인트 · 라이브러리 ·
  프레임워크 · 데이터 타입 · 상태값의 영문 코드 · 캐싱/잠금/마이그레이션 같은 기법 이름.
  필요하면 도메인 문서(`/ib-domain`)나 이슈 본문으로 내린다.
- **한 개념에는 이름 하나.** 기획서에서 정한 용어를 와이어프레임 · 도메인 · 이슈까지 그대로
  쓴다. 기획서가 그 프로젝트 용어의 출처다.
- **상태 · 구분값은 사람이 읽는 우리말로.** `draft` / `approved`가 아니라 *작성 중* / *확정*.
- **비기능 요구사항(5번)은 예외적으로 기술 어휘가 필요할 수 있다.** 그때도 숫자 기준과
  사용자가 체감하는 결과를 함께 적어라 ("동시 접속 500명에서 목록이 2초 안에 뜬다").

| 이렇게 쓰지 말고 | 이렇게 쓴다 |
| --- | --- |
| 기획 엔티티에 status 컬럼을 두고 draft/approved/archived로 관리한다 | 기획서는 *작성 중 · 확정 · 보관* 중 하나의 상태를 가진다 |
| 스냅샷 레코드를 생성해 이력을 적재한다 | 확정된 기획서를 고치면 그 시점의 내용이 이력으로 남는다 |
| JWT 기반 인증 미들웨어로 권한을 검사한다 | 로그인한 사용자만 자기 조직의 자료를 볼 수 있다 |
| 이슈 목록 API에 페이지네이션을 적용한다 | 이슈가 많아도 목록을 나눠 보여 준다 |
